# 0003 单线程累积记忆，不清空、不总结、无独立笔记

- 状态：已采纳
- 日期：2026-09-13

## 背景

最初的需求文档受当时模型上下文长度限制，设计为：公开发言只保留当前任务，任务结束后清空；每名玩家在任务结束时把要点总结进自己的记忆文件。这让游戏结果被"总结写得好不好"污染，与推理能力混在一起，且增加了一个总结步骤。现在采用的模型上下文为 1M，而五人局全程单个玩家线程的规模是常见局 4 到 5 万 token、极端局 12 万左右。

## 决定

每个玩家是一条持续整局的对话线程，只增不删。裁判每次只发送"上次轮到你之后发生的公开事件"加计分板加指令。玩家每次回复分两段：私下分析和公开动作。私下分析以可见文本输出并留在自己的线程中，它的累积就是玩家的跨轮记忆。不清空公开记录，不做总结，不维护独立的记忆文件。

## 后果

- 玩家对自己过去每一步的判断有精确记忆，前后一致性好。
- 每个玩家的线程文件就是"它在每一刻确切看到和想过什么"的完整记录，复盘价值高。
- 必须要求私下分析以可见文本输出。模型的隐藏推理内容不会带回下一次请求，不能依赖它。
- 每次调用重发整条线程，一局累计输入约 300 万 token。依赖前缀缓存和 Flash 级定价把成本压低。
- 长上下文的利用质量会随长度下降，因此裁判每次通知都附精简计分板，关键事实不必从线程里翻。

## 备选方案

- 每次任务清空公开记录加玩家自写总结。被否决，理由如上。保留在 roadmap 供换用短上下文模型时参考。
- 保留全部线程再另加一份"当前判断"笔记。被否决，与线程内容重复。
