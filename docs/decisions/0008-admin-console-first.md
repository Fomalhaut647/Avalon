# 0008 网页界面先做管理员界面，玩家界面暂缓

> 起草日期：2026-09-14

- 状态：已采纳
- 日期：2026-09-14

## 背景

v1 只有终端输出和 markdown 复盘稿，观察和调试五个 AI 玩家要靠翻文件。网页界面有两类受众：管理员以裁判视角看一切；玩家以某个座位的视角只看自己该看的，用于让人类坐进一个座位。两者的信息范围和权限模型不同，不宜一起做。

## 决定

- 先做管理员界面，界面里叫"裁判席"。玩家界面暂缓。
- 裁判席看全部信息：角色、开局所知、每次行动的私下分析、每张任务牌出自谁、开启隐藏思考时的推理原文。
- 界面随对局进度实时演进，并能回放到任一事件；回放只读事件记录，不重新调用模型。
- 视觉方向选"暖纸账簿"：浅色纸底、衬线标题、好人蓝与邪恶红是唯一的强调色。
- 先出静态设计稿，前端技术方案另行决定。设计稿见 [admin-console-design.md](../admin-console-design.md)。

## 后果

- 管理员界面需要的每一项数据都已在现有落盘里，不改裁判逻辑。
- 玩家界面需要按座位过滤信息，届时另写 ADR 定权限模型。
- 设计稿由脚本生成，七块画面的共用构件只有一份源码。

## 备选方案

- **先做玩家界面**：能让人类参与对局，但调试价值低于裁判席，且必须先定权限模型。
- **两者一起做**：范围过大。
- **视觉方向"深色监控台"**：座位环居中，适合投屏盯盘；长段中文在深底上阅读更累。
- **视觉方向"日志流"**：整局一条时间线，复盘最顺、实现最简单；全局态势只剩顶部一行计分条。两块草图保留在画布第二页。
