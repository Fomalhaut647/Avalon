## 一、发言意愿值机制（自由讨论）

v1 的讨论阶段是固定顺序：队长起头，顺时针每人发言一次，最后队长总结并指派队伍。决策理由见 [decisions/0002](decisions/0002-fixed-order-speaking.md)。这种方式简单、可控，但玩家无法"抢话"或"回应"，讨论的动态性不足。

最初的需求文档设计了一套基于"发言意愿值"的自由讨论机制，可作为日后替换固定顺序发言的方向。完整设定如下。

### 1.1 阶段划分

讨论分为两个阶段：

- **开场表态轮（OPENING_STATEMENT）**：每位玩家按固定顺序进行一次正式发言，给出简短看法。玩家可以选择表态，也可以选择"暂时不表态"。这一轮不是"报身份"。
- **自由讨论（DISCUSSION）**：按下面的意愿值规则决定谁发言，反复进行，直到队长发车。

### 1.2 意愿值规则

每一轮对话开始时，所有玩家私下思考，然后各自提交一个整数作为发言意愿值。裁判据此选出一人发言。

- 普通玩家：每次提交的意愿值必须是 0 到 10 的整数。
- 队长：每次提交的意愿值必须是 1 到 12 的整数。队长最低为 1，防止冷场。
- 意愿值为 0 的玩家不能被选中发言。
- 意愿值最高者发言。若最高者不唯一，随机选一人。
- 禁止连续发言：上一轮刚发过言的玩家，下一轮不能再发言。
- 每次一个玩家成功正式发言后，该玩家在本次任务讨论阶段的**意愿值上限**减 1。
- 意愿值上限在每次任务结束后重置为初始值。
- "上限递减 + 禁止连续发言"用于限制对刷，不再额外设置单轮发言次数上限。

### 1.3 裁判的选人流程

1. 所有玩家私下思考并提交意愿值。
2. 裁判过滤掉：意愿值为 0 的、本轮禁止连续发言的、提交非法值的。
3. 从剩余玩家中选意愿值最高者；平局随机。
4. 裁判显式通知被选中者发言。
5. 发言完成后，该玩家意愿值上限减 1。
6. 重复上述流程，直到队长决定发车，或裁判按流程强制进入提案阶段让队长发车。

### 1.4 私密性要求

- 意愿值和私下思考都是私密的，不得进入任何公开记录，也不得被其他玩家看到。
- 只有正式发言写入公开记录。

### 1.5 原文档明确不做的部分

即便启用意愿值机制，原文档也明确排除了：更复杂的抢话机制、回应权机制、多层心智机制。

### 1.6 启用时需要重新考虑的问题

- 队长在什么条件下被"强制发车"，原文档没有说清。需要一个明确的终止条件，比如连续 N 轮全员意愿值为 0，或发言总数达到上限。
- 意愿值上限的初始值原文档没有给出。
- 五个相同模型报出的意愿值可能高度趋同，平局随机会频繁触发，机制的实际效果需要观察。
- 在 chatbot 模型下（见 [decisions/0001](decisions/0001-referee-driven-chatbot-players.md)），"提交意愿值"就是裁判多发一轮"请报意愿值"的通知，每轮对话多 5 次 API 调用，成本需要重新估算。

## 二、基于总结的记忆机制

v1 的做法：公开记录全程完整保留，玩家的私下分析随其对话线程一直保留，不做任何清空和总结。决策理由见 [decisions/0003](decisions/0003-single-thread-memory.md)。

最初需求文档的做法（受当时模型上下文长度限制）：

- 公开发言只保留**当前这次任务**的内容，任务结束后由裁判清空。
- 每次任务结束时（QUEST_RESULT 阶段），要求每个玩家把本次任务的重要信息总结写入自己的私有记忆文件，只记结构化结论，不记原始思维链。
- 建议记录的内容：某玩家在某次任务中的声明或立场、某次任务的队伍与投票结果在自己视角下的含义、当前最重要的怀疑结论及理由、需要记住的承诺与矛盾点、下次发言想推进的点。

日后如果要做以下事情，可以重新考虑这套机制：

- 换用上下文较短或较贵的模型。
- 做更多人数、更多轮次的局，上下文明显膨胀。
- 研究"遗忘"或"信息压缩"对 AI 玩家表现的影响。

需要注意：清空公开记录会让游戏结果受"总结写得好不好"影响，和纯推理能力混在一起，做对比实验时要意识到这一点。

## 三、其他扩展方向

以下是最初需求文档"实现边界"里明确排除、以及设计讨论中提到的方向，v1 均不做。

### 3.1 规则与流程

- 队长指派队伍后允许一轮讨论再投票，更接近真人牌桌。
- 刺杀前允许邪恶阵营公开讨论刺杀目标。
- 邪恶阵营内部的私密沟通渠道。原版规则没有，属于变体。
- 更多人数（6 到 10 人局）与更多角色（Oberon、Mordred、湖中仙女等）。

### 3.2 玩家建模

- 人格系统：给每个座位不同的风格、激进程度、表达习惯，缓解同模型同质化。
- 分身份的策略提示词："如何玩好 Merlin / Percival / Assassin"等。实跑显示梅林几乎必被刺中（见 [experiments.md](experiments.md)），这是最先需要它的地方。
- 每个座位接入不同模型，做模型间对比。见 [decisions/0005](decisions/0005-single-model-all-seats.md)。.env 中已备有 DeepSeek、GLM、Kimi、Qwen、MiniMax、MiMo、Gemini 的 key。
- 让人类坐进一个座位，与 AI 同桌。只需一个从终端读输入的 `Player` 实现。

### 3.3 工程

- GUI 或网页观战界面。
- 网络服务、数据库。
- 批量自动对局与统计：胜率、刺杀命中率、各身份表现。`events.jsonl` 已为此预留。
- 从落盘状态恢复中断的一局。
