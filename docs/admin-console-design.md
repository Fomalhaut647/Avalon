# 管理员界面设计稿

> 起草日期：2026-09-14

本文说明管理员网页界面（界面里叫"裁判席"）的设计稿：画了什么、每块画面对应哪个阶段、数据从哪里来、怎么改稿，以及尚未决定的技术问题。范围决策见 [decisions/0008](decisions/0008-admin-console-first.md)。

设计稿是静态画面，不是可点击原型，也没有任何前端代码。

---

## 一、范围

- 先做管理员界面，玩家界面暂缓。
- 裁判席是上帝视角：五个座位的角色、开局所知的隐藏信息、每次行动的私下分析、每张任务牌出自谁、开启隐藏思考时的推理原文，全部可见。
- 界面随对局进度演进：默认实时跟随，可以把进度拖回任一事件回放，回放不重新调用模型。
- 从任何画面点玩家名字可以下钻到该玩家的完整消息线程。

## 二、画布与源文件

- 画布：<https://claude.ai/code/artifact/8d5fece7-8457-47e2-bcdd-d531649f2210>（私有，Claude Code 设计画布，2026-09-14 第 2 版）。第一页「画面流程」放七块画面，第二页「备选方向（未采用）」放两块低保真草图。
- 源文件在 `design/admin-console/`：

| 文件 | 说明 |
|---|---|
| `build_screens.py` | 生成七块画面的脚本。顶栏、态势条、座位卡、投票格等构件只写一份，七块画面共用 |
| `Lobby.dc.html` 等七个 `.dc.html` | 脚本生成的画板源文件，**不要手改**，改脚本后重新运行 `python3 build_screens.py` |
| `DirectionB.dc.html`、`DirectionC.dc.html` | 手写的低保真备选方向，不再推进 |
| `canvas.json` | 画布布局：分页、每块画板的位置与尺寸、便签 |

- 本地看单块画面：在该目录起一个静态服务（例如 `python3 -m http.server 8765`），浏览器打开对应的 `.dc.html` 即可，静态内容完整可见。
- 重新拼画布并更新到上面的链接需要在 Claude Code 里用 `/design` 技能完成。

## 三、画面清单

| 编号 | 画面 | 对应阶段 | 展示什么 |
|---|---|---|---|
| 0 | 对局列表 | 无 | `games/` 下每局的摘要：局号、开始时间、模型与隐藏思考、任务进度点、状态与结果、用时、费用；右侧「新开一局」的参数等同命令行参数 |
| 1 | 讨论 | DISCUSSION | 五张座位卡；本轮讨论时间线：每条发言与可展开的私下分析、正在生成的玩家显示骨架条和已等待秒数；右侧任务记录与模型调用统计 |
| 2 | 提案与投票 | PROPOSAL、VOTING | 讨论折叠成一行；队长提案与其私下分析；五人并行投票的到达状态，已回的显示赞成或反对，未回的显示等待 |
| 3 | 执行与结算 | QUEST_EXECUTION、QUEST_RESULT | 邪恶队员出牌决定与私下分析；好人由裁判自动出牌的标注；翻牌结果与比分；这块画面同时演示回放态：进度拖回某个事件，顶栏显示「回放中」和「回到实时」 |
| 4 | 刺杀 | ASSASSINATION | 候选人标注、梅林真身标注、刺客正在生成；裁判从对局记录汇总的"刺客可见的公开线索"，供对照它的判断 |
| 5 | 终局 | GAME_OVER | 胜方横幅与原因、刺客最后一手的私下分析、角色公布、四次任务的完整记录、对局统计、产物清单与下载入口 |
| 6 | 玩家线程 | 任意 | 单个玩家发给 API 的整条 `messages` 线程原样展示，私下分析标出"未进入任何人的公开事件"；右侧逐次调用明细与线程规模 |

七块画面用的是同一局假想对局（种子 42）：第 2 次任务 P2 打出失败牌，好人 3 : 1 赢下任务，刺客 P4 刺中梅林 P3。

## 四、共用构件

- **顶栏**：局号、种子、模型、隐藏思考开关；三种状态（实时跟随、回放中、对局已结束）；回放控制五键；事件计数、用时、估算费用。
- **态势条**：五个任务圆圈，圈内是队伍人数，蓝色填充成功、红色填充失败、黑边进行中、虚边未开始；比分；本次任务否决计数五点；阶段步进条（讨论、提案、投票、执行、结算，刺杀阶段追加一格）。
- **座位卡**：座位号、角色、阵营；开局所知；状态标签（队长、队员、已发言、正在发言、投票结果、任务牌）；本局记录（上队次数、出过什么牌）；调用次数与费用。正在行动的座位用粗边框标出。
- **投票格**：五格一行，实心为赞成、空心为反对、虚线为未回。
- **任务牌标签**：写明出牌人，失败牌用红色填充。玩家只看到打乱顺序的牌面，出牌人只有裁判可见。
- **私下分析块**：锁形图标加"仅裁判可见"，默认可折叠，展开显示全文。

## 五、与落盘数据的对应

画面上的每一项都能从现有落盘（见 [architecture.md](architecture.md) 第六节）取到，不需要改裁判逻辑：

| 画面内容 | 来源 |
|---|---|
| 座位、任务、提案、投票、比分、公开发言 | `public.json` |
| 角色、开局所知、私下分析、每张任务牌出自谁、每次调用的耗时、token、费用、隐藏推理 | `events.jsonl` |
| 玩家线程页 | `players/P1.json` 至 `P5.json` |
| 对局列表的结果、用时、费用；终局统计 | `result.json` |
| 回放 | `events.jsonl` 的事件序列按序号切片 |

## 六、未决

以下技术问题在 2026-09-14 尚未决定，未排期，进入前端开发前一次讨论：

1. 实时推送方式：裁判进程主动推事件（WebSocket 或 SSE），还是页面轮询产物文件。
2. 回放在前端本地按事件序号切片，还是由服务端提供切片接口。
3. 裁判席是否允许中途干预对局，例如暂停、终止、重发某次调用。
4. 玩家界面何时做、做成什么样。人类坐进一个座位的想法见 [roadmap.md](roadmap.md) 第 3.2 节。
